# cheap-flights-app

Flight comparison site for Central European travelers. Compares prices from 5 departure airports: Bratislava (BTS), Vienna (VIE), Budapest (BUD), Košice (KSC), Prague (PRG).
Solo project by Lukas. Monetization: affiliate links via Travelpayouts / Aviasales.

Live: https://cheap-flights-app.vercel.app
Repo: github.com/Haldo1231/cheap-flights-app

## About the owner

## Stack
- Next.js 16 (App Router, TypeScript)
- Tailwind CSS
- Supabase (Postgres)
- Vercel (hosting + cron jobs)
- Travelpayouts Data API (free tier, cache-based)

## Key files
- `app/destinationsList.ts`: 12 destination slugs (Rome, Milan, Barcelona, Athens, Paris, London, Berlin, Amsterdam, Lisbon, Warsaw, Krakow, Madrid)
- `app/airportsList.ts`: airport list for the AirportPicker autocomplete
- `/api/cron/generate-deals`: daily Vercel cron that fills the `weekly_deals` table (Bearer token, `CRON_SECRET`)
- Supabase tables: `weekly_deals`, `hostels` (name, booking_url, price_per_night, rating, destination_slug), `destinations`, and the price store `price_tickets`, `price_coverage`, `price_runs`, `price_jobs` (`supabase/price_store.sql`, run once by the owner; `price_overview` and `price_store_stats` functions).
- THE PRICE STORE (how every price reaches a screen): `app/lib/tpV3.ts` = the Travelpayouts v3 "prices for dates" method (month summaries with `unique=true` = every destination of an airport with its cheapest ticket; route-months = one ticket per day, or per departure+return day; real tickets with airline, flight number, time, booking site, deep link; no `found_at` in the data, so `found_at` = when we fetched it; the month guard and one-way/round-trip checks are in `normalizeV3`). `app/lib/priceStore.ts` = reads/writes (upsert key origin+destination+departure_date+return_date+one_way; Supabase answers at most 1000 rows, reads page). `app/lib/priceSource.ts` = STORE FIRST, LIVE FALLBACK: `routePairTickets` / `routeMonthTickets` / `overviewTickets` read the store when fresh (`FRESH_HOURS` = 48), else fetch live, store and `console.warn('[prices] live fallback …')`; live fails → stored rows with their real age (`console.error`); store unusable → the live answer directly; route-months are remembered in-process for a minute. `/api/cron/refresh-prices` (vercel.json 02:00 UTC, Bearer `CRON_SECRET`) = the nightly job: summaries for the 5 airports × this month + 3 (`coveredMonths`), then for the 12 named + 25 cheapest destinations of each summary all three kinds (rt out, ow out, ow back); time-boxed slices (`PRICE_REFRESH_BUDGET_MS`, default 50 s) that call themselves (`continueRun`, `?run=ID`, `PRICE_REFRESH_SELF_URL` / `VERCEL_PROJECT_PRODUCTION_URL`), paced ≤ ~190 requests/min, log in `price_runs` / `price_jobs`, departed days deleted. `/api/debug-prices?key=…&store=1` = store status. The token travels in the `X-Access-Token` header (`app/lib/travelpayouts.ts`, `tpFetch`), never in an address.
- `app/flightSources.ts`: the flight/fare shapes and every read the screens use (`getDayFlights[From]`, `getRangeFlights[From]`, `getMonthDaysByOrigin`, `getOneWayFares`, `findOpenJawPairs`, `getReturnFares`, `getCheapestFare`), all through the price store. The old endpoints (`fetchLatest`, `fetchMonthCalendarDetailed`, `fetchMonthOneWayDays`) are DEBUG ONLY (`/api/debug-prices`). A fare with a return date is ONE price for both flights; never split it per leg. `buildBookingLink(origin, destination, depart, return, link?)` opens the exact ticket when the store has its deep link (marker 765816 always).
- Price rules (in `app/flightSources.ts`, `app/weekdays.ts`, `app/lib/priceAge.ts`): "cheapest" = the MINIMUM valid price (never the first listed fare); a route-month older than 48 h (`price_coverage.fetched_at`) is refreshed live before it is shown; stale prices (`found_at` older than 72 h) are dropped by the old debug paths; an answer not in euro is discarded (`currencyIsEuro`); `Fare.seenAt` carries `found_at` and the UI says "price seen 6 h ago" or "price age not in the data" (`PriceAge`); a calendar/cheap entry WITH a return date is a round-trip price, never added to another price (`findBestCombinations`, `monthSelection`); month searches only count days INSIDE the searched month (`fetchMonthCalendarDetailed` drops other days) and a round trip must return in the return month (`findBestCombinations(..., months)`); a one-way Anywhere check never takes a fare with a return date, and Anywhere shows no "example" fare that was not checked against the filters; the open-jaw legs use `getCheapestOneWayLeg`. `/api/debug-prices` (off unless `DEBUG_PRICES_KEY` is set) shows raw Travelpayouts answers for checking.
- Return to a different home airport (the switch "Fly back to a different airport", `ReturnAirportSwitch`, URL `openJaw`, OFF by default): a different-airport trip is two one-way tickets (out from A, back to B, A != B; a round-trip fare is never reused). `useResultsParams` returns `openJawAllowed` (round trip, and not Anywhere / `fromCountry` + Whole month) and the effective `openJaw` (false when not allowed, also for hand-edited links). `findOpenJawPairs` (`app/flightSources.ts`) pairs the one-way fares for exact dates and date range; `openJawFilterFor` (`app/openJawFilter.ts`) builds the day windows. One-way fares come from the one-way list plus calendar entries without a return date (`getOneWayFares`).
  - DESTINATION page (`DestinationView`): the main price is always the cheapest same-airport round trip; `/api/compare?openJaw=true` returns the pairs, `DestinationView` asks for both lists (`openJaw=false` for the normal fares) and `OpenJawContent` renders the second one; the cheapest pair becomes the extra line under the switch (`DifferentAirportLine`: "BTS → Barcelona → PRG, €68 (+€8 vs round trip)"; no pair = no line, the section below says "No cached fares for returning to a different airport on these dates.").
  - ANYWHERE (exact dates / date range only): ONE mixed list, no sections and no extra line. `/api/anywhere-jaw` (`checkCityOpenJaw`: out from ANY chosen airport, back to any home airport, one-way lists only, no calendars; returns nothing for one way and for Whole month) is a SECOND request. `lib/anywhereJaw.ts` (`mixJawIntoCity`, `mixJawIntoCountries`, `mixJawIntoCities`) mixes it into the lists: each card / row shows the CHEAPER of the round trip and the different-airport trip (`cheaperTrip` in `lib/tripRoute.ts`: the jaw trip must be strictly cheaper, a tie keeps the round trip), the list and the country "from EUR X" use that price, a country/city with only a different-airport trip moves out of "no matching day". `tripRouteLabel` (`lib/tripRoute.ts`, pure, also used by the server) words every trip: "round trip, back to BTS" / "two one-way tickets, back to PRG"; the label is only shown while the switch is ON (`routeLabel` prop of `CountryCard` / `AnywhereCityRow`), OFF keeps the old wording exactly. A mixed city carries `roundTripPrice` (client only) for the note "−€9 vs round trip (round trip from the same airport: €28)". `openJaw` is not part of the main price request (`dataFilters`); `JawStatus` is the status line (`found` = cities with a different-airport trip, `used` = how many are cheaper and shown). `countryShareCard` (`lib/shareData.ts`) follows the same rule when the link has `openJaw=true`.
- Whole month, round trip (the city page, `MonthContent` / `useMonthTrip`): the two calendars show ONE-WAY prices only (`/api/calendar?oneWay=true`: the day's cheapest one-way ticket from/to any chosen airport; the plain calendar answer is round-trip only, checked on the owner's real paste). One-way prices come from `fetchMonthOneWayDays` (the one-way latest list `one_way=true`, rows with no return date, plus calendar entries with no return date). "Best combinations" is ONE list: round-trip fares (the plain outbound answer `calRoundTrip` + the date-range list `fareList`, labelled "round-trip fare") and "2 one-way tickets" (the two one-way calendars), cheapest total first. The picked days give the sum of two one-way tickets with a booking link per ticket (`FlightLeg` compact `searchLinkLabel`); a cheaper round-trip fare for the same two days is the alternative shown next to the total (`roundTripAlt`, `TripSummary`). A round-trip pick keeps its own return day (no flight back is added to it, see `roundTripOutbound`). Day lists on this page are one-way only (`dayOnly`). The combinations' requests start after the outbound calendar has come back, so they are answered from the server cache.
- Copy rows (`isCopyRow` in `app/flightSources.ts`): a latest-prices row with `gate` empty, `duration` 0 and `distance` 0 is dropped (`normalizeFromLatest`); a calendar entry whose `departure_at` day is not its key is dropped (`fetchMonthCalendarDetailed`). Applies to every search.
- Whole Month and the different airport: Anywhere + Whole month has NO switch (search form hides it, `openJaw` is read as false). A destination + Whole month has the switch (`MonthContent`): ON + an outbound picked, the Returning calendar (`CalendarGrid` with `notes`: airport under the price, badge "−4" = cheaper than the same-airport return) shows the cheapest flight back to ANY home airport per day (`lib/returnMonth.ts`: `useReturnMonth` = ONE `/api/return-flights` request for the month, `returnCalendar`); `useMonthTrip` then reads the day's flights from it, and `monthSelection(..., oneWayOut)` adds the chosen flight back to the ONE-WAY outbound (`oneWayOutbound`: the picked fare if one-way, else the cheapest cached one-way fare from the same airport that day, else a plain-language problem). The button "Fly back to a different airport" in `TripSummary` (any Whole month round trip, also after Anywhere) opens `/back` in month mode with that one-way outbound (`backHref(..., { bm: 'month', bmon, bx: '1' })`).
- Anywhere (`app/anywhereSearch.ts`): `rankCountries(origins, anywhereMonths(params), oneWay, token)` ranks every destination of the store's month summaries for the searched months (`anywhereMonths`: the month, the exact date's month, or the range's months, max 4). The "honest check" (`checkCity`) checks every city from EVERY chosen home airport with the SAME store rows as the city page: month modes read `getMonthDaysByOrigin` (round trip: rt out + ow out + ow back, like the city page's Best combinations, the cheaper of a fare and two one-way tickets per airport); exact dates / date range read `getDayFlightsFrom` / `getRangeFlightsFrom` (one store read per city). The routes have `maxDuration = 60`. `MAX_ORIGINS_PER_CITY` only limits the rough "from" options kept by the ranking.
- `/api/debug-prices` (off unless `DEBUG_PRICES_KEY` is set) also has a month mode (`month=YYYY-MM&origins=...&destination=...&oneWay=true`, `app/lib/debugMonth.ts`): per day what the calendar shows, from which list, and which entries of `/v2/prices/latest` LOOK LIKE COPIES (`looksLikeFiller`: no `gate`, `duration` 0 and `distance` 0). ## Known limitations (not bugs)
- Travelpayouts free data is cached: small routes (e.g. KSC → Prague) can return no results.
- Prices can be stale, so always show them as "from €X".
- Some cached fares have no airline or departure time. Show "Airline not in data" instead of guessing. Never invent flight data.
- The price store is refreshed once a night; a route-month a visitor asks for that is not in it (or older than 48 h) costs a live request per airport and kind, then it is in the store. If a live answer is 429 (too many requests), the stored rows (if any) are shown and the failure is logged.
- The nightly job's self-chaining (one function call starting the next slice) was tested locally and on the first production run must be checked in `price_runs` (status `done`, no `abandoned` note); Vercel's function limit (60 s legacy, 300 s with Fluid compute) decides the slice size (`PRICE_REFRESH_BUDGET_MS`).
- Whole Month round trip: the country screen pairs days inside each airport, the city page's "Best combinations" may also pair a flight out from one airport with a flight back to another, so the country screen can say "no matching day" for a city whose page lists such a pair.
- Verified with real data (Nov 2026): `one_way=true` returns only one-way rows (v2 and v3); v3 answers have no copy rows and no days outside the asked month; v3 round-trip prices per day equal the old calendar's; the `market` parameter changed neither the tickets nor the deep links on the route tested (default kept).
- Anywhere's round-trip Whole month check (`checkCityMonth`) counts round-trip fares only. The city page also counts two one-way tickets, so for a city where two one-way tickets are cheaper, the country's price can be higher than the city's cheapest. Open decision (see PROGRESS.md).
- Whole Month "out + back" combines two separate cached prices; the calendar prices may themselves be round-trip fares, so that sum can overstate the real cost.
- The public API routes (`/api/*`) have input cleaning and caching but no per-visitor rate limit.
- Link-preview pictures use the built-in font (no bold weight), so the heavy text is thickened with a stroke. A shared trip page shows the price stored in its own link (as the page always did).
